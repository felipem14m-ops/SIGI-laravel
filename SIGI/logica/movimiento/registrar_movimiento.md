# Registrar Movimiento de Inventario

La lógica de esta funcionalidad se maneja principalmente desde el controlador `MovimientoController.php` y la vista `Admin/Movimiento/ListasdeMovimiento.blade.php`.

Para realizar esta acción, el usuario autenticado interactúa con la opción "Nuevo Movimiento" que se encuentra disponible mediante un botón modal en la vista de lista de movimientos o en las acciones del catálogo de productos. La acción del formulario está configurada para enviar los datos al controlador `MovimientoController.php` a través de la ruta con nombre `movimientos.store`, que corresponde a la URL `/movimientos` mediante una petición de tipo `POST`. Esta ruta está protegida por el middleware `auth`, garantizando que solo usuarios autenticados puedan modificar las existencias del inventario.

Al recibir la petición `POST`, el método `store` de la clase `MovimientoController` ejecuta en primer lugar la validación de los datos de entrada mediante `$request->validate`. El sistema comprueba que el identificador `id_producto` no esté vacío y corresponda a un registro existente en la tabla `productos`, que la `cantidad` sea un valor entero mayor o igual a 1, que el parámetro `tipo` sea una cadena válida entre las opciones permitidas (`entrada`, `salida`, `ajuste`), y que el campo `motivo` no exceda los 255 caracteres. Si alguna de estas reglas no se cumple, Laravel interrumpe el flujo y redirige al usuario de vuelta con los mensajes de error correspondientes, o devuelve un objeto JSON con error 422 si la petición espera una respuesta en formato JSON.

Una vez superada la validación, el controlador obtiene el modelo del producto correspondiente mediante `Producto::findOrFail($request->id_producto)`. A continuación, determina el código del tipo de movimiento. Si el formulario envió el campo `tipo`, convierte la cadena a mayúsculas (`ENTRADA`, `SALIDA` o `AJUSTE`). En caso de no recibirlo directamente, intenta buscar el registro en el modelo `TipoMovimiento` a través de `id_tipo_movimiento`. Luego, el controlador verifica o crea el registro en la tabla `tipos_movimiento` utilizando `TipoMovimiento::firstOrCreate()`, asignando el signo correspondiente (`-` para salidas y `+` para entradas o ajustes).

Antes de modificar el stock, el controlador guarda en la variable `$stockAnterior` el valor de `stock_actual` que posee el producto en ese instante. Esta variable es fundamental para preservar el histórico y la trazabilidad del inventario.

Posteriormente, el controlador evalúa la lógica del movimiento según el tipo especificado:
1. **Movimiento de Salida (`SALIDA`)**: El controlador comprueba que el `stock_actual` disponible sea mayor o igual a la cantidad que se desea retirar. Si el stock es insuficiente, el proceso se detiene inmediatamente, evitando saldos negativos y retornando un mensaje de error ("Stock insuficiente. Disponible: X"). Si hay existencias suficientes, resta la cantidad del atributo `stock_actual` (`$producto->stock_actual -= $cantidad`).
2. **Movimiento de Entrada (`ENTRADA`)**: Incrementa directamente el valor de la cantidad recibida sobre el `stock_actual` (`$producto->stock_actual += $cantidad`).
3. **Movimiento de Ajuste (`AJUSTE`)**: Asigna de forma directa la cantidad especificada como el nuevo valor absoluto de `stock_actual` (`$producto->stock_actual = $cantidad`).

Una vez calculado el nuevo saldo, el controlador ejecuta `$producto->save()`, actualizando el registro en la tabla `productos`. Inmediatamente después, invoca el método `Movimiento::create()` para registrar la transacción de auditoría en la tabla `movimiento_inventario`. Este objeto se llena con el `id_producto`, el `id_usuario` del usuario autenticado obtenido con `auth()->id()`, el `id_tipo_movimiento`, la `cantidad` del movimiento, el `stock_anterior`, el `stock_resultante`, el `motivo` (o en su defecto el texto por defecto "Ajuste manual") y la `fecha` actual en formato `YYYY-MM-DD`.

Al finalizar la operación con éxito, el controlador verifica si la petición requería una respuesta JSON. Si es así, retorna un objeto de éxito con el mensaje "Movimiento registrado correctamente.". De lo contrario, ejecuta `back()->with('success', 'Movimiento de inventario registrado correctamente.')`, provocando que la vista redirija al usuario al panel de movimientos y muestre una notificación de confirmación en la interfaz. Si ocurre alguna excepción durante el proceso, el bloque `try-catch` captura el error y retorna una alerta explicativa al usuario sin comprometer la integridad de la base de datos.
